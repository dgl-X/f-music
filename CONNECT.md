# Family Music Connect

Экспериментальная функция позволяет выбрать, где играет музыка, и управлять
этим плеером из другого WEB- или Android-клиента того же аккаунта.

## Как включить

В `.env` сервера задайте:

```dotenv
MUSIC_CONNECT_ENABLED=true
```

Перезапустите `family-music`. Старые клиенты продолжат работать: новые маршруты
добавлены в API v1, а функция по умолчанию выключена.

## Как это работает

1. Клиент регистрирует случайный ID, имя, тип и возможности устройства.
2. Polling раз в 1,5 секунды одновременно служит heartbeat и каналом команд.
3. «Слушать на…» отправляет целевому плееру очередь, текущий трек и позицию.
4. Только после успешного ACK сервер назначает новый активный плеер и ставит
   прежний на паузу.
5. Play/pause, переходы, seek, shuffle, repeat и громкость направляются активному
   устройству. Аудио не проходит через управляющий клиент.

Команды ограничены аккаунтом и живут 30 секунд. При потерянном ACK команда может
быть доставлена повторно, но клиент сохраняет результат её первого выполнения и
повторяет только ACK. Состояния применяются по монотонной серверной ревизии, а
исходящие снимки одного клиента отправляются последовательно. Каждая передача
увеличивает `playback_epoch`: сервер и клиенты отклоняют снимки и команды от
предыдущего владельца плеера. WEB требует явного нажатия кнопки Connect перед
приёмом воспроизведения из-за browser autoplay policy.

Быстрый список «Слушать на…» показывает только устройства, которые сейчас
online и объявили готовность принимать воспроизведение. Закрытые вкладки WEB
остаются в истории устройств до отзыва или серверной очистки, но не засоряют
переключатель.

Активное устройство владеет плеером, пока присылает heartbeat. Если heartbeat
не приходит 35 секунд, сервер атомарно освобождает владельца, помечает состояние
остановленным и отменяет его ожидающие команды. Вернувшийся плеер либо другое
устройство может занять новую `playback_epoch`; старый снимок уже не перезапишет
нового владельца. Управляющий WEB-клиент возвращает свою локальную карточку, но
не запускает звук автоматически, чтобы краткий сетевой обрыв не создал два
одновременно играющих плеера.

Серверный smoke-тест выполняется отдельным обычным аккаунтом без доступа к
музыке: `CONNECT_TEST_USERNAME=... CONNECT_TEST_PASSWORD=... npm run
test:connect:smoke`. Тест проверяет повторную доставку до ACK, идемпотентный ACK,
смену эпохи, отклонение старого снимка и отмену команды прежнего владельца, после
чего удаляет созданные им виртуальные устройства. В CI тот же сценарий запускает
собственный API и одноразовый PostgreSQL командой `npm run
test:connect:integration`.

## Ограничения первого MVP

- транспорт пока HTTP polling, без WebSocket;
- Android гарантированно принимает команды, пока клиентский процесс жив;
- функция выключена по умолчанию; оператор может включить её для контролируемой
  полевой проверки гонок передачи, быстрых переключений и потери сети;
- WEB и Android игнорируют повторный snapshot с той же ревизией, чтобы polling
  не сбрасывал локальный плавный отсчёт позиции;
- Android восстанавливает переданную очередь в порядке списка ID, независимо от
  порядка ответа `/tracks/resolve`, и выбирает текущий элемент строго по ID;
- освобождение владельца после длительного offline реализовано; восстановление
  после реальных Wi-Fi/LTE-разрывов проходит полевую проверку.
