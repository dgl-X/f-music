# План URL-навигации WEB

Статус: основные маршруты, F5, browser history, настройки и внутренний 404
реализованы 24 сентября 2026 года; продолжается ручная проверка на production.

## Цель

Каждый основной экран должен иметь постоянный адрес. Обновление страницы,
прямая ссылка и кнопки браузера «Назад»/«Вперёд» должны восстанавливать тот же
раздел, не сбрасывая пользователя на «Мне нравится». Переходы внутри приложения
остаются клиентскими и не прерывают текущий плеер.

## Карта маршрутов

| URL | Экран |
| --- | --- |
| `/liked` | «Мне нравится» |
| `/recommendations` | «Для вас» |
| `/search` | общий и федеративный поиск |
| `/tracks` | все треки |
| `/history` | недавно прослушанные |
| `/artists` | каталог исполнителей |
| `/artists/{id}` | карточка исполнителя |
| `/albums` | каталог альбомов |
| `/albums/{id}` | карточка альбома |
| `/playlists` | список плейлистов |
| `/playlists/{id}` | содержимое плейлиста |
| `/upload` | загрузка музыки |
| `/settings` | пользовательские настройки |

Административные разделы позднее получат вложенные адреса
`/settings/statistics`, `/settings/users`, `/settings/federation`,
`/settings/recognition` и `/settings/reports`. Обычному пользователю они не
отдаются даже при прямом вводе URL.

Поиск, сортировка и пагинация кодируются в query string, например:

```text
/tracks?q=guf&scope=local&sort=album&page=2&page_size=50
/search?q=город&node=node-id&kind=tracks&page=1
```

В URL нельзя помещать session cookie, федеративные подписи, remote reference,
ключи API и другие секреты.

## Этап 1. Клиентский router

1. Вынести разбор `location.pathname` и query string в небольшие чистые функции.
2. Добавить однозначное преобразование URL в существующее состояние
   `activeView`, `activeAlbumId`, `activeArtistId`, `activePlaylist`, фильтры и
   номер страницы.
3. Добавить обратное преобразование состояния в канонический URL.
4. Все пользовательские переходы выполнять через `history.pushState()`;
   смену фильтра, сортировки и страницы — через `replaceState()` либо
   `pushState()` по единому правилу.
5. Обработать `popstate`, не перезагружая документ и не пересоздавая аудиоплеер.
6. `/` после входа канонически заменять на `/liked`; до входа этот же адрес
   продолжает показывать авторизацию или мастер первоначальной настройки.

## Этап 2. Карточки и прямые ссылки

1. Открывать исполнителей, альбомы и плейлисты по стабильным ID, а не только по
   текстовым названиям.
2. При F5 сначала восстанавливать маршрут, затем запрашивать его данные.
3. Для удалённого или недоступного объекта показывать понятный экран `404`, не
   сбрасывая весь интерфейс на главную вкладку.
4. Сохранять текстовые параметры только как fallback для старых серверов;
   канонические ссылки строить по ID.

## Этап 3. Плеер и состояние

1. Навигация внутри WEB не должна менять очередь, текущий трек, позицию,
   shuffle, repeat и предзагрузку.
2. Полное обновление страницы восстанавливает плеер через существующий
   `/api/v1/playback-state`.
3. Открытие карточки текущего трека не должно создавать новую очередь.
4. Выход из аккаунта очищает клиентскую историю экрана и переводит на `/`;
   после повторного входа открывается ранее запрошенный разрешённый маршрут либо
   `/liked`.
5. Недоступный федеративный трек пропускается существующей логикой, не ломая
   URL открытого каталога.

## Этап 4. Сервер и reverse proxy

Сервер уже возвращает `index.html` для неизвестного статического пути после
обработки `/api`, `/api/v1`, `/federation/v1` и служебных маршрутов. Поэтому
основной nginx может продолжать проксировать запрос целиком в приложение.

Нужно закрепить тестами, что:

- `GET /albums/123` и остальные WEB-маршруты возвращают SPA;
- реальные `app.js`, `app.css` и модули отдаются как файлы;
- неизвестный `/api/v1/...` остаётся API-ошибкой, а не HTML;
- media, federation и health-маршруты не перехватываются router fallback;
- одинаковое поведение сохраняется при прямом доступе к VM и через публичный
  reverse proxy.

## Этап 5. Тестирование и выпуск

1. Unit-тесты parser/serializer для всех маршрутов, Unicode query и ошибочных ID.
2. Проверка прямого открытия каждого URL в новой вкладке и после F5.
3. Проверка цепочки «альбом → исполнитель → назад → вперёд».
4. Проверка фильтра, поиска, сортировки и пагинации после обновления страницы.
5. Проверка непрерывного воспроизведения при 20–30 переходах между разделами.
6. Проверка обычного пользователя и администратора на прямых `/settings/...`.
7. Smoke-тест через публичную HTTPS-точку и локальную точку входа.
8. После успешного production-теста актуализировать README, ARCHITECTURE и
   release notes.

## Совместимость и внедрение

- API v1 и Android не меняются.
- Старые закладки на `/` продолжают работать.
- Неизвестный WEB-маршрут показывает внутренний `404` с переходом в библиотеку.
- Внедрение выполняется сначала для вкладок и карточек, затем для настроек;
  каждый этап можно откатить без миграции базы.
- Публичные ссылки не предоставляют доступ без действующей авторизованной
  сессии.

## Критерий готовности

Работа завершена, когда пользователь может открыть конкретный альбом, нажать
F5 и остаться в этом альбоме; кнопки «Назад»/«Вперёд» восстанавливают экраны и
фильтры, а музыка продолжает играть без перезапуска.
