# Участие в разработке

Спасибо за интерес к Family Music. Проект ориентирован на небольшие домашние
инсталляции, предсказуемое обновление и сохранность пользовательской медиатеки.

## Перед изменением

- для ошибки создайте Issue с минимальными шагами воспроизведения;
- для крупной функции сначала опишите сценарий и влияние на API/хранилище;
- вопросы безопасности отправляйте по [`SECURITY.md`](SECURITY.md), а не публичным
  Issue;
- не добавляйте код загрузки музыки из источников, нарушающих права владельцев.

## Локальная проверка сервера

Нужны Node.js 24+, PostgreSQL и FFmpeg/ffprobe.

```bash
npm ci
npm test
node scripts/check-repository-secrets.mjs
node scripts/check-git-history-secrets.mjs
```

Перед PR также выполните `git diff --check`. Изменения схемы должны быть
идемпотентными и сохранять rolling compatibility с предыдущей версией.

## Android

Android-клиент разрабатывается в отдельном репозитории. Для проверки нужны JDK 17
и Android SDK 36:

```bash
./gradlew --no-daemon testDebugUnitTest assembleDebug
```

Release-keystore для обычной разработки не нужен и никогда не должен попадать в
PR. Серверный API v1 нельзя менять только ради клиента без совместимого перехода.

## Правила PR

- один PR решает одну связанную задачу;
- описание и пользовательские тексты желательно писать по-русски;
- новый функционал сопровождается тестами и обновлением документации;
- API и federation JSON расширяются только совместимыми необязательными полями;
- данные пользователя, адреса инфраструктуры, токены и реальные журналы запрещены;
- generated APK, DEB, кэш и медиатека не коммитятся.

Отправляя изменение, участник соглашается распространять его на условиях лицензии
соответствующего репозитория: AGPL-3.0-only для сервера или GPL-3.0-only для
Android.
