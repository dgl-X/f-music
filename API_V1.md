# Family Music API v1

Стабильный контракт для WEB и Android-клиента. Базовый путь: `/api/v1`. Все
ответы с JSON используют `Content-Type: application/json`. Поле `error` остаётся
совместимым со старыми клиентами, а каждый JSON-ответ с HTTP-кодом `4xx/5xx`
дополнительно содержит стабильные поля `error_code`, `retryable` и `request_id`.
Последний совпадает с заголовком `X-Request-ID` и позволяет найти запрос в
серверном журнале. Клиентская логика должна опираться на `error_code`, а не на
русский текст сообщения.

```json
{
  "error": "Трек не найден",
  "error_code": "not_found",
  "retryable": false,
  "request_id": "d7784e76-72de-4fb0-bde9-c530bd330be4"
}
```

## Совместимость

- В пределах v1 существующие поля и маршруты не удаляются и не меняют смысл.
- Новые необязательные поля могут добавляться без смены версии; клиент должен игнорировать неизвестные поля.
- Ломающие изменения публикуются только под новым префиксом `/api/v2`.
- Старые пути `/api/*` без номера версии отключены и возвращают `410 Gone` с
  кодом `api_version_retired` и ссылкой на `/api/v1` в заголовке `Link`.

## Авторизация

`POST /login` принимает `{username,password}` и устанавливает `music_session` как `HttpOnly; Secure; SameSite=Strict` cookie. Web и Android должны сохранять cookie и отправлять её во всех последующих запросах. Самостоятельная регистрация опциональна и по умолчанию выключена.

- `GET /setup/status` — состояние мастера: `needs_setup`, версия сервера,
  название библиотеки, `registration_enabled` и безопасные проверки БД, storage и worker.
- `POST /setup` — атомарно создать первого администратора и сохранить
  `library_name`/`recognition_enabled`, только при пустой БД.
- `POST /login` — войти.
- `POST /register` — создать обычный аккаунт, только когда регистрация включена;
  ограничено пятью попытками на IP в час.
- `POST /logout` — завершить текущий сеанс.
- `GET /me` — текущий пользователь.
- `GET /sessions` — безопасный список собственных активных входов с устройством, клиентом, IP и последней активностью; токены и их хэши не возвращаются.
- `DELETE /sessions/{id}` — завершить выбранную собственную сессию.
- `DELETE /sessions/others` — завершить все собственные сессии, кроме текущей.
- `PUT /me/password` — `{current_password,new_password}`.
- `GET /users` — список аккаунтов, только администратор.
- `POST /users` — `{username,display_name,password}`, только администратор.
- `GET|PUT /admin/registration-settings` — прочитать или изменить состояние
  самостоятельной регистрации, только администратор.
- `PUT /users/{id}/password` — `{new_password}`, только администратор.
- `GET /admin/stats` — агрегаты библиотеки, пользователей, диска, очередей и проверка наличия медиафайлов; только администратор.
- `GET /admin/metrics` — heartbeat API/worker, память, HTTP 5xx, состояния и
  возраст очередей, новые отчёты, ошибки за сутки и агрегаты длительности
  обработки загрузок, транскодирования, loudness, федеративных sync/import;
  только администратор.
- `GET /metrics/zabbix` — ограниченные эксплуатационные метрики по отдельному `Bearer`-токену `MUSIC_METRICS_TOKEN`; пользовательские данные и секреты не возвращаются.

Изменяющие cookie-запросы требуют корректный заголовок `Origin`. Ответы: `401` без сеанса, `403` без прав или при недоверенном Origin, `429` после превышения попыток входа.

## Каталог и файлы

- `GET /tracks?q=&artist=&artist_id=&album=&album_id=&liked=1&playlist_id=&sort=&limit=&offset=` — постраничный локальный каталог; ответ содержит `total`, `has_more`, `limit` и `offset`. При фильтрации по `artist_id` каждый трек получает `artist_role` (`primary` или `featured`). `album_id` выбирает точную карточку альбома, включая треки с `feat.`. Старые текстовые фильтры продолжают работать.
- `GET /favorites?q=&sort=&limit=&offset=` — единая пагинированная лента локальных лайков и ещё не завершённых федеративных импортов; `queue=1` допускает очередь до 10 000 элементов.
- `GET /library?scope=all|local|remote&q=&sort=&limit=&offset=` — единый пагинированный каталог локальных и федеративных треков. В `all` уже импортированный трек показывается один раз как локальный; `queue=1` допускает очередь до 10 000 элементов.
- `sort=random&seed=` — воспроизводимый случайный порядок по всей выбранной коллекции; Android использует его для глобального shuffle.
- `POST /tracks/resolve` с `{ids:[...]}` — восстановить метаданные очереди в переданном порядке, до 10 000 локальных UUID и/или `remote:<opaque-ref>`.
- `GET /catalog` — исполнители и альбомы; у альбома есть стабильный `id`, `name`, `artist`, `bio`, `image_url`, `track_count`.
- `GET /artists/{id}` — карточка исполнителя с описанием, изображением, агрегатами и связанными альбомами; у релиза есть `artist_role`, общее `track_count` и отдельное `credited_track_count`. Собственные альбомы идут перед участиями, внутри групп — от новых к старым.
- `GET /albums/{id}` — карточка альбома.
- `PATCH /albums/{id}` — изменить описание `{bio}`; администратор или владелец всех треков альбома.
- `PUT|DELETE /albums/{id}/image` — загрузить или удалить обложку карточки; те же права.
- `GET /albums/{id}/image` — получить обложку карточки.
- `PATCH /tracks/{id}` — изменить `title`, `artist`, `album`, `genre`, `year`.
- `DELETE /tracks/{id}` — удалить трек и принадлежащие ему файлы.
- `GET /tracks/{id}/stream?quality=auto|original|high|compact` — оригинал либо общая производная AAC 192/AAC 96 с поддержкой одного HTTP Range (`200`, `206`, `416`). Если выбранная AAC-копия ещё не готова, сервер ставит её в очередь и сразу отдаёт оригинал без задержки воспроизведения.
- `GET /tracks/{id}/cover` — JPEG-обложка.
- `PUT /tracks/{id}/cover` — тело с изображением до 12 МиБ.
- `DELETE /tracks/{id}/cover` — удалить обложку.
- `PUT|DELETE /tracks/{id}/like` — добавить или убрать сердечко.
- `POST /tracks/batch` — пакетно оформить альбом: `{album_id?,artist,album,genre,year,items:[{id,disc_number,track_number}]}`. Ответ содержит `album_id`. Поле `artist` задаёт исполнителя альбома и не переписывает исполнителей песен; пустой жанр и год `null` сохраняют индивидуальные значения треков.

Элемент трека содержит `id`, `title`, `artist`, `album`, `album_id`, `filename`, `mime_type`, `size_bytes`, `duration_seconds`, `created_at`, `cover_url`, `genre`, `year`, `track_number`, `disc_number`, `liked`, `aac_192_ready`, `aac_96_ready`.

`GET /tracks/{id}/stream?quality=original&prepare=aac_192` отдаёт неизменяемый оригинал и одновременно ставит указанный AAC-вариант в фоновую очередь. Клиент переключается на `quality=aac_192` только после появления `aac_192_ready=true`, поэтому разные представления файла не смешиваются в одном HTTP-кэше.

В приватной версии 0.1.33 `quality=source` выдаёт точные
загруженные байты. Для гибридного FLAC `quality=original` может выдавать отдельно
сохранённый lossless-вариант (`X-Music-Variant: normalized_flac`), без замены
исходного файла. Готовая AAC-копия сохраняет приоритет при выборе AAC-качества.

`GET /tracks/{id}/playback?quality=original&codecs=mp3,aac,flac` выбирает источник.
Обязательный список `codecs` описывает возможности клиента. Ответ содержит
`status: ready|preparing|failed|unsupported`, `variant`, `codec`, `lossless` и,
если файл готов, `stream_url` и `size_bytes` выбранного файла (или null, если
размер неизвестен). Размер нужен клиенту для корректного Range/seek даже при
частичной предзагрузке. При подготовке возвращается `retry_after_ms`;
если поддерживаемый оригинал уже доступен, он отдаётся сразу, а
`requested_variant`/`preparation_status` описывают фоновую подготовку AAC.
Обычный опрос не перезапускает failed-задание; явный `retry=1` разрешает повтор.
При запросе `/stream` с `codecs` неподдерживаемый оригинал не используется:
подготовка/ошибка дают `409`, отсутствие подходящего кодека — `415`.
Ссылка `stream_url` закрепляет фактический `variant`: если он стал недоступен,
сервер возвращает `409 media_variant_changed`, а не подставляет другой файл
в тот же кэш. Без `codecs` старое поведение сохраняется для прежних клиентов.
WEB и Android 1.0.57 используют контракт для локальных треков; удалённое
воспроизведение и внешний предпросмотр сохраняют прежний путь. AAC получает
ready только после ffprobe и полного декодирования с проверкой длительности.

Сортировки: `newest`, `oldest`, `title`, `artist`, `album`, `year`.

`GET /recommendations` возвращает персональные секции из локальной медиатеки: недавние прослушивания, ежедневный микс понравившихся, давно не звучавшие треки, новые поступления и подборки по наиболее часто слушаемым жанрам. Внешние сервисы не используются.

## Возобновляемая загрузка

1. `POST /uploads` с `{filename,size,mime_type}` возвращает `201` и `{id,offset,size}`.
2. `HEAD /uploads/{id}` возвращает `Upload-Offset`, `Upload-Length`, `Upload-Status`.
3. `PUT /uploads/{id}` принимает chunk с `Content-Range: bytes start-end/total`.
4. Последний chunk возвращает `202` и `{offset,complete:true,processing:true}`.
5. `GET /uploads/{id}` опрашивается до конечного состояния.

`GET /uploads` возвращает до 100 последних загрузок текущего пользователя для истории и диагностики.

Ответ состояния: `{id,offset,size,status,error,track_id}`. Возможные статусы:

- `uploading` — принимаются части;
- `processing` — worker вычисляет SHA-256, читает теги и обложку;
- `ready` — `track_id` указывает созданный трек;
- `duplicate` — `track_id` указывает уже существующий трек;
- `failed` — причина находится в `error`.

Chunk обязан начинаться ровно с подтверждённого offset. При расхождении сервер возвращает `409` и `expected_offset`. Максимальный размер файла по умолчанию — 1 ГиБ.

## Плейлисты и воспроизведение

- `GET|POST /playlists` — список (включая `track_count`, `duration_seconds`, `cover_track_id`) или создание `{title,description}`.
- `PATCH|DELETE /playlists/{id}` — изменение или удаление.
- `POST /playlists/{id}/tracks` — `{track_id}`.
- `DELETE /playlists/{id}/tracks/{trackId}` — убрать трек.
- `GET|POST|DELETE /playlists/{id}/remote?ref=` — получить, добавить или убрать удалённую песню; старые клиенты могут игнорировать этот маршрут.
- `GET /history` — последние 200 треков.
- `POST /history` — `{track_id}`, отметить запуск.
- `GET /playback-state` — текущий локальный или удалённый трек, позиция, очередь, её отображаемый источник, shuffle и repeat.
- `PUT /playback-state` — сохранить `{track_id,position_seconds,queue,queue_source,shuffle,repeat_mode}`; ID очереди могут быть локальными UUID или `remote:<opaque-ref>`.

`repeat_mode`: `off`, `all` или `one`; очередь ограничена 10 000 уникальными ID и телом запроса до 1 МиБ.

## Family Music Connect (экспериментально)

Маршруты доступны только при `MUSIC_CONNECT_ENABLED=true`. Все устройства
принадлежат текущему пользователю; клиент не может видеть устройства или
управлять воспроизведением другого аккаунта.

- `GET /connect/status` — доступность функции и рекомендуемый интервал polling.
- `GET|PUT /connect/settings` — персональная настройка текущего аккаунта.
  PUT принимает `{enabled:boolean}`; GET возвращает `user_enabled`,
  `server_enabled` и эффективное `enabled`. Доступно и при выключенном Connect;
  выбор другого пользователя через тело или query не поддерживается.
- `POST /connect/devices` — зарегистрировать/обновить `{id,name,client_type,capabilities}`.
- `GET /connect/devices` — собственные online/offline устройства и текущее состояние.
- `DELETE /connect/devices/{id}` — отозвать устройство.
- `GET|PUT /connect/state` — получить или обновить состояние активного плеера.
- `POST /connect/transfer` — передать snapshot очереди выбранному устройству.
- `POST /connect/commands` — отправить `play`, `pause`, `next`, `previous`,
  `seek`, `set_shuffle`, `set_repeat` или `set_volume` активному устройству.
- `GET /connect/commands?device_id=&after=` — heartbeat и получение следующей команды.
- `POST /connect/commands/{id}/ack` — подтвердить выполнение либо ошибку.

Состояние содержит монотонные `revision` и `playback_epoch`. `revision` задаёт
порядок снимков внутри одной эпохи, а `playback_epoch` меняется при передаче
воспроизведения другому устройству. Клиент обязан отправлять текущую эпоху в
`PUT /connect/state`; устаревший снимок получает `409 connect_stale_epoch`.

С приватного выпуска 0.1.32 поддерживаются необязательные
`is_playing` (фактическое воспроизведение), `buffering` и `playback_status`
(`playing`, `buffering`, `waiting`, `paused`, `preparing`). `playing` сохраняет
значение намерения Play для кнопок и передачи воспроизведения. Позиция движется
только при фактическом воспроизведении. Без новых полей действует прежняя
семантика `playing`; изменения совместимы со старыми клиентами.

Команды имеют TTL 30 секунд. Успешная передача меняет активное устройство
только после ACK получателя; повторная доставка возможна при потере ответа.

С 0.1.31 capability `transfer_prepare` включает подготовку приёмника на паузе.
ACK передаёт `result.state` с фактическим треком и позицией. После подготовки
сервер запрашивает `deactivate` источника и выдаёт приёмнику `activate` после
подтверждённой остановки. Обычные команды в этот период получают
`409 connect_transfer_pending`. Старые клиенты сохраняют прежний контракт.
Необязательные `shuffle_order` и `playback_history` содержат ID перестановки и
истории; неизвестные и отсутствующие в очереди ID фильтруются. State, transfer
и ACK принимают JSON до 2 МиБ, включая большие очереди.

### SSE-подсказки Connect — приватный этап 0.1.34 / 1.0.58

При `MUSIC_CONNECT_EVENTS_ENABLED=true` статус дополнительно объявляет
`transports: ["sse","polling"]`, `events_url` и `events_heartbeat_ms`.
`GET /connect/events?device_id=...` требует cookie-сессию и устройство своего
аккаунта. Поток отправляет только `event: resync` с `data: {}`; клиент затем
читает обычные API. При переподключении сверка обязательна, команды остаются
в БД до прежнего ACK. Поддержка SSE не меняет polling и выключена по умолчанию.
Лимиты, проверка отзыва доступа и этапы клиентов описаны в
[`CONNECT_SSE.md`](CONNECT_SSE.md). WEB и Android 1.0.58 используют SSE лишь
при объявленной сервером возможности, иначе остаётся polling. Старые клиенты
совместимы; при обрыве или недоступности потока работает прежний опрос.

## Федеративный пользовательский каталог

- `GET /federation/nodes` — доступные пользователю подключённые ноды и количество их песен.
- `GET /federation/search?q=&node_id=&limit=&offset=` — поиск либо просмотр полного каталога выбранной ноды в локально синхронизированном индексе.
- `GET /federation/liked?limit=&offset=` — персональные понравившиеся треки с подключённых нод.
- `GET /federation/track?ref=` — карточка удалённого трека по opaque reference.
- `POST /federation/prepare` с `{ref,quality}` — безошибочно поставить AAC-вариант в очередь и получить `{ready,retry_after_ms}`.
- `GET /federation/stream?ref=&quality=original|aac_96|aac_192` — оригинал либо AAC через домашний сервер; origin и его ключи клиенту не передаются. WEB использует оригинал без ожидания транскодирования.
- `GET /federation/replica?ref=` — состояние фонового импорта (`queued`, `downloading`, `retry`, `imported`, `removed`), прогресс, локальный ID и последняя ошибка.
- `POST /federation/replica?ref=` — повторить импорт; трек должен находиться в персональном «Мне нравится».
- `DELETE /federation/replica?ref=` — отменить ещё не завершённый импорт. Готовый импорт удаляется как обычный локальный трек.
- `PUT|DELETE /federation/like?ref=` — сохранить или убрать персональный лайк удалённого трека на домашней ноде.

Для администратора `POST /admin/federation/peers/{node_id}/check` немедленно
проверяет HTTPS endpoint и закреплённый identity подключённой ноды, сбрасывает
stream circuit breaker при успехе и ставит синхронизацию каталога в очередь.
Ответ содержит только результат, `node_id` и задержку; закрытые ключи и секреты
pairing никогда не возвращаются.

Удалённый DTO имеет стабильный `id` вида `remote:<opaque-ref>`, признаки `remote` и `liked`, поле `remote_ref`, домашний `stream_url` и необязательные `replica_status`, `replica_received_bytes`, `replica_size_bytes`. Клиент не должен разбирать opaque reference или обращаться к origin напрямую. Старые клиенты могут продолжать использовать только локальные UUID.

После завершения импорта карточка удалённого DTO содержит `local_track_id`. WEB использует его для перехода к обычной редактируемой карточке локального трека. Если в оригинале нет встроенной картинки, worker запрашивает доступную обложку с origin по подписанному федеративному маршруту.

## Необязательный источник OpenVK

- `GET|PUT /admin/openvk-settings` — включить источник и сохранить либо удалить access token; доступно только администратору, сохранённый токен никогда не возвращается клиенту.
- `GET /openvk/search?q=&limit=&offset=` — проксированный поиск для авторизованного WEB-клиента. Ответ содержит только нормализованные метаданные и `source_id`, без токена и прямого URL файла.
- `GET /openvk/stream?source_id=` — авторизованное предпрослушивание через сервер с поддержкой одного HTTP Range; CDN-ссылка и токен не передаются браузеру.
- `POST /openvk/import` с `{source_id}` — скачать оригинал с фиксированного HTTPS CDN OpenVK и поставить его в штатную очередь проверки и обработки.

OpenVK не участвует в запуске сервера и работе локальной библиотеки. Повторный импорт определяется по `track_sources`; после обработки файл становится обычным локальным треком и больше не зависит от внешнего источника.

## Альбомы и общие обложки

- `POST /tracks/batch` — применить общие метаданные и порядок к группе треков.
- `PUT /tracks/batch-cover` — один раз принять и преобразовать изображение, затем назначить его трекам из заголовка `X-Track-Ids`; максимум 150 ID и 12 МиБ.

## Диагностические отчёты

- `POST /reports` — отправить описание и безопасный журнал приложения.

Подготовлено локально: журнал текущей Android-сессии дополняется безопасными
блоками `session`, `media` и `smart_cache`. Они принимают только разрешённые
скалярные поля; URL, произвольные заголовки и секреты в этих блоках отбрасываются.
Размер JSON details ограничен 96 000 символами, тело запроса — 128 КиБ.
Android ограничивает журнал 600 событиями/32 КиБ, а сами записи очищаются
от URL и секретов до помещения в память. Старые отчёты остаются совместимыми.
- `GET /admin/reports` — последние 100 отчётов для администратора.
- `PATCH /admin/reports/{id}` — установить статус `new`, `viewed` или `fixed`.
- `DELETE /admin/reports/{id}` — удалить отчёт.

## Распознавание файлов без тегов

Маршруты доступны только администратору. Загрузка и воспроизведение не зависят от внешнего сервиса: распознавание выполняется отдельным worker после сохранения оригинала. Результат с итоговой уверенностью от 80% автоматически заполняет название, исполнителя, альбом и год, а при наличии загружает обложку Cover Art Archive. Сборники, DJ-mix, live и remix не выбираются как основной альбом. Менее уверенные варианты ждут подтверждения.

- `GET /recognition` — очередь, отклонённые записи и треки без обложки; для каждого результата возвращается до пяти вариантов.
- `POST /recognition/scan` — поставить в очередь уже существующие треки с неизвестным исполнителем.
- `POST /recognition/retry-all` — повторно поставить в очередь все отклонённые, не найденные и завершившиеся ошибкой записи.
- `POST /recognition/{id}/apply` с `{candidate:0}` — применить выбранные название и исполнителя.
- `POST /recognition/{id}/manual` с `{title,artist,album,genre,year}` — сохранить метаданные вручную.
- `POST /recognition/{id}/ignore` — оставить текущие теги.
- `POST /recognition/{id}/retry` — повторить неудачный или пустой поиск.

## Служебный маршрут

`GET /health` не требует авторизации, проверяет соединение с PostgreSQL и доступ
к хранилищу и возвращает `200` со статусом `ok` либо `503` со статусом
`degraded`. Все маршруты v1 содержат заголовок ответа `X-API-Version: 1`.
