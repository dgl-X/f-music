# Накопительные выпуски

Небольшие дефекты записываются и исправляются пакетами, обычно по 3–7 за цикл.
Каждая мелочь не должна создавать отдельный APK или серверный релиз.

## Рабочий цикл

1. Записать дефект, шаги воспроизведения и ожидаемое поведение; Android-дефекты
   вести в `android/KNOWN_ISSUES.md`, общий набор — в `RELEASE_BATCH.md`.
2. Накопить связанные исправления в приватной разработке. Коммиты могут быть
   небольшими; номер версии и release tag повышаются для всего набора.
3. После примерно 3–7 исправлений проверить тесты, собрать приватные DEB/APK и
   выложить сервер на production для контролируемой проверки.
4. Проверить WEB и Android в обычном использовании, включая обратную связь
   владельца. Найденные мелочи добавлять в текущий набор, не запускать новый
   выпуск автоматически после каждого замечания.
5. После подтверждения работы перенести очищенный набор в публичные репозитории
   и выпустить публичные DEB/APK с описанием всего набора изменений.

В списке различать «записано», «исправлено», «автоматически проверено» и
«подтверждено полевой проверкой». Незавершённую проверку нельзя считать
подтверждением готовности public. Критический сбой рассматривается отдельно.
