# DEB-пакет Family Music

Экспериментальный пакет предназначен для Debian 13 amd64. Он устанавливает код,
проверенный официальный Node.js 24 runtime в `/opt/family-music`, два
systemd-сервиса и примеры конфигурации. Системный Node.js не заменяется. PostgreSQL,
медиатека, федеративная identity и `.env` не удаляются при обновлении или
удалении пакета.

## Сборка

```bash
npm ci --omit=dev
./packaging/build-deb.sh 0.1.0 amd64
```

Результат появляется в `dist/family-music-server_0.1.0_amd64.deb`.
Сборщик загружает официальный Node.js 24.20.0 один раз в игнорируемый Git
локальный кэш и перед упаковкой сверяет закреплённый SHA-256.

## GitHub Release

Тег формата `vX.Y.Z` запускает отдельный workflow: тесты, проверку репозитория,
сборку DEB и публикацию пакета вместе с `SHA256SUMS`.

```bash
git tag -a v0.1.0 -m "Family Music Server v0.1.0"
git push origin v0.1.0
```

Версия DEB берётся из тега. Перед отправкой тега следует убедиться, что commit в
`main` прошёл обычный workflow `Проверка сервера`; повторное использование уже
опубликованного тега не поддерживается.

## Установка и обновление

```bash
apt install ./family-music-server_0.1.0_amd64.deb
systemctl status family-music family-music-worker
node -e "fetch('http://127.0.0.1:8095/api/health').then(async r => { console.log(await r.text()); process.exit(r.ok ? 0 : 1) })"
```

При первой установке пакет создаёт системного пользователя, локальную роль и БД
PostgreSQL, каталоги хранения и шаблон `/opt/family-music/.env`. Перед запуском
следует проверить `.env` и настроить nginx по примеру из
`/usr/share/doc/family-music-server/examples/`.

`postinst` ждёт успешного `/api/v1/health` и проверяет оба systemd-сервиса. Если
API не готов за 30 секунд, `apt` завершает настройку пакета ошибкой и показывает
состояние служб вместо ложного сообщения об успешной установке.

Локальная роль PostgreSQL не получает `CREATEDB`, `CREATEROLE` или права
суперпользователя. База `family_music` принадлежит только этой роли; соединение
по умолчанию выполняется через локальный Unix socket. При первом старте API и
worker автоматически создают недостающие таблицы под advisory lock.

На уже работающей ручной установке существующие `.env`, `storage` и база данных
используются без переноса. Перед первым пакетным обновлением всё равно нужен
snapshot или проверенная резервная копия.

## Проверка в чистом Proxmox LXC

Для расходного Debian 13 LXC доступен smoke-тест установки и обновления:

```bash
./scripts/deb-lxc-smoke.sh 107 \
  ./dist/family-music-server_0.1.1_amd64.deb \
  ./dist/family-music-server_0.1.2_amd64.deb
```

Скрипт запускается на хосте Proxmox VE и принимает уже созданный и запущенный
VMID. Он устанавливает пакет через `apt`, проверяет API, PostgreSQL и оба
systemd-сервиса, создаёт тестовые данные, обновляет пакет, перезагружает LXC и
проверяет сохранность БД и storage. Скрипт изменяет и перезагружает указанный
контейнер, поэтому его нельзя направлять на production.

Создание и удаление LXC намеренно не автоматизированы: имена storage, bridge,
DHCP и требования к изоляции различаются между установками Proxmox.

## Удаление

```bash
apt remove family-music-server
```

Удаляются код и службы. Музыка, `.env` и PostgreSQL остаются на сервере.
