# Транскодирование аудио

Оригинал сохраняется неизменным. Подготовленные варианты хранятся отдельно
и переиспользуются всеми пользователями.

## Варианты

- `original` — оригинал либо совместимый подготовленный контейнер.
- `source` — точные исходные байты; контракт описан в [API_V1.md](API_V1.md).
- `aac_192` — AAC-LC в M4A, около 192 кбит/с.
- `aac_96` — AAC-LC в M4A, около 96 кбит/с.

Lossless-оригиналы не заменяются lossy-файлами. AAC кодируется на CPU:
видеокодировщики NVENC не ускоряют этот процесс.

## Хранение и выдача

Таблица `track_files` хранит вариант, codec, bitrate, размер, storage key
и состояние. Производные размещаются в `storage/derived/` и публикуются
атомарным переименованием после успешной обработки.

`GET /api/v1/tracks/{id}/stream?quality=auto|original|high|compact` выбирает
доступный вариант; `high` соответствует AAC 192, `compact` — AAC 96.
Если производная не готова, обработка ставится в очередь, а старт не должен
ждать завершения FFmpeg. Заголовок `X-Music-Variant` сообщает фактический
вариант. Поддерживается HTTP Range.

## Измерение производительности

```bash
scripts/benchmark-transcoding.sh /путь/к/аудиофайлу 3
```

Скрипт измеряет время, RSS, размер результата и скорость относительно
длительности аудио; временные файлы удаляются после завершения.
Параллелизм выбирайте по CPU, памяти и дисковой нагрузке конкретного сервера.
