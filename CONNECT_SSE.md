# SSE для Family Music Connect

## Статус

Основа выпущена в сервере 0.1.34 и Android 1.0.58. Текущий набор 0.1.35 / 1.0.59
установлен на production и опубликован в приватном/публичном предварительном
канале. SSE включён на production, WEB проверен через HTTPS reverse proxy.
Android использует отдельный фоновый поток с polling-fallback. По умолчанию
`MUSIC_CONNECT_EVENTS_ENABLED=false`; общий и персональный Connect также должны
быть включены. `transport: polling` сохранён для прежних клиентов.

## Протокол

Авторизованный `GET /api/v1/connect/events?device_id=<registered-device-id>`
возвращает `text/event-stream`. Используется обычная cookie-сессия; ID устройства
не является авторизацией. Проверяются аккаунт, действующая сессия, срок её
действия, принадлежность устройства, отсутствие отзыва и персональная настройка.

Первый ответ содержит `retry: 1500` и событие:

```text
event: resync
data: {}

```

Это только сигнал прочитать существующие `/connect/commands` и `/connect/state`.
В потоке нет команд, названий песен, очередей, секретов или отдельного playback
state. Успешные операции будят клиентов своего аккаунта после завершения записи
или COMMIT, не после отката. ACK, revision, playback_epoch и дедупликация не меняются.

Повторная отправка сигнала допустима. `Last-Event-ID` не даёт право доступа и
не используется как durable cursor: после каждого подключения обязательна полная
сверка pending commands и текущего состояния. Потеря соединения не удаляет команду.

## Ограничения и восстановление

- Каждые 15 секунд отправляется проверенный resync, поддерживающий соединение
  и периодическую сверку; через 5 минут поток штатно закрывается для переподключения.
- Перед каждым последующим сигналом проверяется доступ. Отзыв сессии/устройства
  закрывает поток при следующем сигнале, максимум через heartbeat; персональное
  отключение Connect будит и закрывает потоки аккаунта сразу.
- Лимиты: 128 соединений на процесс, 8 на аккаунт, 2 на устройство. Превышение
  возвращает 429. Медленный получатель отключается, события не копятся в памяти.
- Изменения быстро распространяются внутри **одного API-процесса**. Между
  процессами пока нет PostgreSQL LISTEN/NOTIFY; остаётся периодическая сверка.
- SSE учитывается в журнале запросов, но длительность открытого потока не
  увеличивает среднюю задержку API и счётчик медленных запросов.

## nginx и проверки

Сервер устанавливает `X-Accel-Buffering: no`, `Cache-Control: private, no-store,
no-transform` и `Content-Encoding: identity`. На каждом прокси-хопе проверить
buffering, gzip и read timeout: тайм-аут должен превышать heartbeat с запасом.
На production обнаружена буферизация на внешнем nginx: внутренний прокси
поглощал `X-Accel-Buffering`, и внешний не получал этот заголовок. Для сайта
музыки на внешнем хопе явно выключен `proxy_buffering`; nginx проверен и reload
выполнен. HTTPS-проверка после исправления: подсказка команды за 22 мс, ACK и
закрытие потока при персональном отключении успешны. Это задержка подсказки,
не задержка старта аудио. Конфигурация до изменения сохранена.

Проверка 2026-10-14: на отдельной VM прошёл PostgreSQL/HTTP-сценарий, затем тот
же поток проверен через временный nginx с намеренно включённым buffering:
заголовок приложения отключил буферизацию, события дошли до закрытия ответа.
Полный локальный серверный набор: 379 passed, один opt-in тест без внешнего
аудиообразца skipped, ошибок нет. Временные БД и прокси очищены.

Unit-проверки: `node --test test/connect-events.test.js test/connect-http.test.js`.
PostgreSQL/HTTP: `CONNECT_TEST_DATABASE_URL=... npm run test:connect:integration`
на отдельной пустой тестовой БД. Для проверки через внешний тестовый nginx
задать `CONNECT_TEST_EVENTS_ORIGIN`, оставив API на `CONNECT_TEST_PORT`.

## Следующие этапы

1. WEB: реализованы EventSource, единая последовательная сверка по подсказкам,
   watchdog, reconnect с backoff 1,5–30 секунд и polling-fallback. При здоровом
   потоке быстрый опрос не выполняется; старт и каждый reconnect сверяют состояние.
   Статус возможностей обновляется раз в 15 секунд даже при включённом Connect.
   Ошибки REST API также возвращают fallback без бесконечного немедленного retry.
   Logout/отключение закрывают поток и отбрасывают поздние события. Проигранная
   команда не выполняется повторно при повторном сигнале или повторе ACK.
2. Android: реализован отдельный фоновый поток, отмена при logout/смене сервера,
   reconnect с backoff и polling-fallback. Заголовок Cookie остаётся в HTTPS,
   redirects запрещены; SSE-парсер ограничивает размер кадра 16 КиБ.
   Wi-Fi/LTE/Doze требуют полевой проверки.
3. WEB: отсутствие feedback loop и повторного исполнения команды проверено.
   В Android собственный snapshot больше не генерирует локальные Player events:
   повторная публикация не запускается. Команды исполняются последовательно,
   ACK повторяется без повторного исполнения команды.
4. Стенд и приватный production-выпуск проверены. Следующий этап — телефон:
   переключения, шторка, перенос WEB ↔ Android, обрывы Wi-Fi/LTE и Doze.
   Публичный выпуск — после подтверждения обычным использованием.

WEB-проверка использует сам `ConnectClient` и нативный WHATWG EventSource Node
через HTTP/PostgreSQL. Первая команда доставляется при отключённом таймере
polling; проверяются дубли, принудительный обрыв, fallback, reconnect и
персональное выключение. Это не проверка HTML/audio в настоящем браузере.
`npm run test:connect:integration` включает необходимый Node-флаг автоматически;
при прямом запуске скрипта нужен `--experimental-eventsource`.
Итог WEB-этапа: 391 passed, один opt-in skipped; интеграционный сценарий повторён
через временный nginx с включённым buffering. Временные БД/прокси удалены,
тестовая VM после WEB-этапа была выключена.

Android-этап: 75 unit/Robolectric-тестов и debug-сборка успешны. Проверены
пакеты подсказок, последовательность запросов, потеря ACK без повторного next,
fallback/reconnect, старый сервер, logout и персональное отключение. Отдельная
регрессия исключает повторную отправку состояния в ответ на локальный snapshot.
Полный PostgreSQL/HTTP/WEB-сценарий повторён на VM перед приватным выпуском.
