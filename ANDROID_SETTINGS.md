# Настройки сервера в Android

Доступно в Android 1.0.62 / сервере 0.1.39. Настройки качества, кэша,
загрузок и воспроизведения сохранены.

SettingsRequests учитывает lifecycle
экрана, сервер и вход; ответы в фоне ждут возвращения, устаревшие отбрасываются.
Повтор загрузки всегда снова проверяет `/me`. Одновременные записи блокируются,
автоматического повтора неподтверждённой мутации нет.
Серверная операция не откатывается закрытием экрана.

## Доступные разделы

Нативные полноэкранные страницы:

- личная статистика: 7 дней, 30 дней, всё время, топы, согласие на сбор и очистка;
- Family Music Connect: включение для своего аккаунта на всех устройствах;
- смена своего пароля с завершением остальных сессий;
- только администратору: AcoustID и OpenVK — включение, замена и удаление ключа;
- только администратору: список аккаунтов, создание обычного пользователя,
  сброс чужого пароля с подтверждением и завершением его сессий;
- только администратору: отчёты — последние 100 сообщений, фильтр по статусу,
  страницы по 20, подробности и журнал, изменение статуса и удаление с подтверждением;
- библиотека по умолчанию: общая, локальная или удалённая — выбор этого устройства;
- только администратору: состояние сервера, метрики, очереди, последние ошибки,
  анализ громкости, агрегаты использования и настройка регистрации.

Дубликаты, управление федерацией и «Требуют внимания» оставлены только в обычном
WEB. В Android нет этих пунктов, а переходы к ним из встроенных настроек
заблокированы. Это не отключает воспроизведение федеративных треков.
Полная WEB-диагностика остаётся дополнительным экраном из состояния сервера.

## Совместимость и безопасность

Перед открытием проверяются текущая сессия и роль через `/api/v1/me`.
Администраторские API независимо проверяют права на сервере. Запросы закреплены
за исходными адресом и сессией; запоздавший ответ другого входа не применяется.

Для встроенных страниц сервер должен возвращать
`features.android_settings_portal: 1` из `/api/v1/setup/status`. Старый сервер
получит понятное предложение обновиться, без передачи cookie в старую страницу.
WebView разрешает только HTTPS текущего origin и переходы между настройками.
Cookie передаётся как Secure/HttpOnly, не в URL или JavaScript. Нет JS-моста,
доступа к локальным файлам, обхода TLS и сторонних переходов. Системный выбор
файлов передаёт только явно выбранные пользователем `content://` URI.

WEB-портал не восстанавливает плеер, не сохраняет очередь и не регистрирует
второе устройство Connect или сборщик прослушиваний. Явное предпрослушивание
приостанавливает локальное аудио; удалённый исполнитель не затрагивается.
Загрузка файлов из портала заблокирована: для неё нужен обычный браузер.

Настройки AcoustID/OpenVK используют нативные формы и существующие GET/PUT API.
Пустое поле сохраняет прежний секрет; удаление требует явного выбора и
подтверждения. Секрет не сохраняется в состоянии Activity и не подставляется
обратно с сервера; на этих экранах отключены autofill и снимки экрана.
Сам поиск OpenVK остаётся только в WEB, в Android переносится лишь настройка.

Управление аккаунтами использует `/users` и `/users/{id}/password`. Свой пароль
меняется только в профиле. Удаление аккаунтов и выдача ролей не добавляются:
такой возможности нет в текущем API. Формы пароля не сохраняются при повороте
экрана, не используют autofill и защищены от снимков; POST не повторяется
автоматически при потере ответа. После сетевой ошибки следует обновить список,
прежде чем повторять создание аккаунта.

Экран отчётов использует GET `/admin/reports`, PATCH и DELETE
`/admin/reports/{id}`. Статусы: `new`, `viewed`, `fixed`; по умолчанию показаны
новые. Список фильтруется локально среди последних 100, не по всей истории.
API пока передаёт эти отчёты вместе с подробностями; пагинация интерфейса не
уменьшает размер ответа. Отрисовываются только подробности открытого отчёта.
Журнал ограничен первыми 600 событиями, по 50 на странице, строка до 1024
символов с явным многоточием. Известные диагностические поля выводятся текстом,
без HTML, автоматических ссылок и экспорта. Просмотр сам по себе не меняет статус.

## Проверка

В отдельном Android-репозитории `./gradlew --no-daemon testDebugUnitTest assembleDebug` проверяет
каталог разделов, роли, URI, форматы статистики и контекст очереди.
`npm test` проверяет изоляцию WEB-портала. HTTP/PostgreSQL-интеграция:
`STATISTICS_TEST_DATABASE_URL=... npm run test:statistics:integration`
(только отдельная пустая БД).

Перед выпуском проверить на телефоне два аккаунта, поворот экрана, возврат
назад, системный выбор изображения, предпрослушивание, потерю сети и смену
сервера. Автотесты не заменяют проверку настоящего WebView.
