# Координация фоновых очередей

Начиная с 0.1.38 обработчик держит shared advisory lock PostgreSQL от получения
задания до завершения его побочных действий. Восстановление той же очереди
требует exclusive lock. Это защищает весь срок работы, а не только короткий
`SELECT … FOR UPDATE SKIP LOCKED` при получении задания.

Пять независимых областей: uploads, transcode, loudness, recognition, replicas.
Shared блокировки позволяют нескольким процессам работать параллельно.
Ожидающий exclusive lock не пропускает новые задания; уже работающие завершаются.
Ожидание восстановления ограничено 30 секундами; при таймауте повтор выполняется
периодической проверкой раз в минуту. До опустошения активных обработчиков
осиротевшее задание может оставаться processing: это сознательный приоритет
безопасности перед немедленным повтором.

Блокировки используют отдельный pool (до 10 соединений на процесс), чтобы
длительные задачи не исчерпали обычный pool запросов (также до 10). Учитывать
оба pool при настройке PostgreSQL max_connections и числа процессов.
При потере координационного соединения процесс завершается с кодом 1.
Контролируемый выход убивает запущенные им медиапроцессы. systemd должен
сохранять KillMode=control-group: SIGKILL отдельного PID вне systemd не даёт
гарантии завершения всех его дочерних процессов.

Это кооперативный протокол, не изоляция старых бинарников и не per-job fencing.
Обновление: остановить ВСЕ старые worker и API до замены исходников, затем
запустить новую версию. Rolling upgrade со старыми обработчиками одной БД
не поддерживается. Новые таблицы/колонки не требуются, API v1 не изменён.
API также использует эти guards для ручного запуска анализа/сканирования.

Проверка в отдельной пустой БД:

```sh
WORKER_TEST_DATABASE_URL=postgresql:///fm_worker_test_local npm run test:worker:integration
```

Сценарий оставляет синтетические строки в выделенной БД; создавать и удалять
её отдельно. Проверяются живой владелец, SIGKILL, потеря соединения, все пять
областей, параллелизм и освобождение блокировки при исключении.
