# Реализация федерации Family Music

Нормативный протокол и модель доверия описаны в [FEDERATION.md](FEDERATION.md).
Этот документ описывает компоненты проекта, а не конфигурацию конкретных нод.

## Границы

Локальная музыка не зависит от доступности федерации. Peer связываются вручную;
адрес источника сетевого запроса не заменяет проверку Ed25519-подписи.
Публичные HTTPS-endpoint и точные private endpoint проверяются отдельно,
с защитой от SSRF, DNS rebinding и redirects.

## Реализованные компоненты

- Стабильная identity, JSON Schema descriptor, capabilities и версии протокола.
- Одноразовое pairing-приглашение, двусторонний challenge и отзыв доверия.
- Подписанные snapshot/delta, revision/cursor и защита от replay.
- Notify как подсказка обновления и периодический polling для восстановления.
- Политики публикации `none/all/albums/collections` и отдельные правила peer.
- Объединённый каталог, поиск и просмотр библиотеки другой ноды.
- Подписанные потоки оригиналов с HTTP Range и ограничением параллелизма.
- Локальное копирование понравившегося оригинала с докачкой и SHA-256.
- Backoff, circuit breaker и исключение недоступных peer из новых очередей.
- Административные метрики и отдельный ограниченный endpoint Zabbix.

После успешного копирования трек становится локальным: дальнейшее воспроизведение
не должно зависеть от исходной ноды.

## Совместимость

Возможности определяются общим major, minor и capabilities, а не угадываются
по версии приложения. Неизвестные необязательные поля и события допускаются;
неизвестное обязательное событие останавливает применение страницы без
продвижения cursor. Изменения API v1 должны оставаться совместимыми.

Baseline `v0.1.1` и контрольные суммы схем находятся в
`federation/compat/baseline-v0.1.1.json`. Тесты проверяют старого producer
с текущим reader и обратное направление.

## Проверки

```sh
npm run test:federation:two-node
```

Используйте отдельные тестовые PostgreSQL-базы. Дополнительные smoke-сценарии
находятся в `scripts/federation-*-smoke.mjs`; перед запуском прочитайте скрипт:
некоторые создают временные аккаунты, импортируют аудио или меняют настройки peer.

Проверяйте pairing/revoke, подписи, replay, ACL каталога и потоков, Range/416,
лимиты потоков, offline/reconnect, rolling upgrade и сохранность локальных данных.
Автоматический двухнодовый сценарий не заменяет проверку реальных DNS, TLS
и reverse proxy конкретной установки.
