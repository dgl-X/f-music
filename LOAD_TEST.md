# Нагрузочный тест большой библиотеки

Сценарий использует отдельную PostgreSQL-базу с синтетическими треками.
Не запускайте его на рабочей базе или медиахранилище.

## Набор данных

- 10 000 треков;
- 500 исполнителей и 1 000 альбомов;
- 2 500 лайков и 5 000 записей истории;
- 20 плейлистов по 200 треков;
- сохранённая очередь из 10 000 ID.

## Повторение

Создайте отдельную базу, имя которой заканчивается на `_loadtest`, примените
обычные миграции запуском API и выполните:

```bash
psql "$LOADTEST_DATABASE_URL" -f scripts/load-test-seed.sql
```

Скрипт намеренно завершится ошибкой для базы без суффикса `_loadtest`.

Полноценная проверка Android, где все 10 000 записей можно воспроизводить,
описана отдельно в [`ANDROID_LOAD_TEST.md`](ANDROID_LOAD_TEST.md).

## Федеративные аудиопотоки

На уже сопряжённой ноде тест запускается от пользователя сервиса:

```bash
sudo -u family-music node scripts/federation-stream-smoke.mjs
```

Скрипт сам выбирает доступный удалённый трек и проверяет:

- четыре разрешённых входящих потока и отклонение пятого с HTTP `429`;
- освобождение всех слотов после принудительного обрыва клиентов;
- ответ `206` и ровно 1024 байта для partial Range;
- ответ `416` для диапазона за концом файла;
- успешный новый Range-запрос после ошибки.

Проверка не изменяет базу и медиатеку. Для полноценного двустороннего прогона
её следует выполнить последовательно на обеих сопряжённых нодах.

Полный цикл локального импорта проверяется отдельным скриптом. Он создаёт
временного пользователя, ставит лайк свободному удалённому треку, ждёт worker,
проверяет появление обычного UUID-трека в общем «Мне нравится», локальный Range,
удаление промежуточного remote-like и полностью очищает тестовые данные:

```bash
runuser -u family-music -- node scripts/federation-replica-smoke.mjs
```
