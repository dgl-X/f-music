1. **Статистика отозванных нод.** Исправлено локально: основные счётчики
   удалённых треков, offline, sync/notify и возраста синхронизации учитывают
   только действующие ноды. Сохранённый каталог учитывается отдельно в

   Регрессионная проверка SQL добавлена. Выкладка пока не выполнялась.

2. **Медиатракт: неизменяемый оригинал и отдельная lossless-перепаковка.**
   Подготовлено локально: гибридный FLAC больше не заменяется исправленным файлом.
   Исходные байты, размер и SHA-256 остаются в `tracks`; проверенный вариант
   `normalized_flac` хранится в `track_files`. Он повторно исследуется ffprobe,
   полностью декодируется и используется для воспроизведения и подготовки AAC.
   `quality=source` выдаёт именно загруженные байты; обычный `quality=original`
   может использовать lossless-перепаковку. Backup включает эти варианты.
   Реальный FLAC проверяется отдельно через `F_MUSIC_TEST_ORIGINAL_FILE`:
   загрузка, сохранность хеша, полное декодирование, длительность, HTTP Range и
   точное совпадение PCM после перепаковки. Прод и репозитории не обновлялись.
   Полный прогон с копией настоящего FLAC: **333/333 теста**, без пропусков.
   PCM сравнивался в 32-битном представлении; оригинал на production остался
   побайтово неизменным. Гибридный тестовый контейнер построен из того же аудио
   без перекодирования — это проверка сценария, не найденный дефект этого трека.

   Следующие этапы: явные состояния подготовки совместимого файла; выбор по
   возможностям клиента вместо неподдерживаемого fallback; повторная проверка
   готовых AAC; дополнительные сценарии повреждения, отмены и восстановления.

3. **Общая подготовка аудио при федеративном импорте.** Реализовано локально:
   загрузка и импорт используют `audio-preparation.js`. Перед созданием локального
   трека выполняются ffprobe, полная проверка декодирования и при необходимости
   отдельная lossless-перепаковка. Длительность и codec берутся из файла, а не
   из доверенного на слово каталога соседа. Оригинал и его SHA-256 не меняются.
   Проверенный SHA-256 сохраняется до финализации, чтобы после сбоя не скачивать
   файл повторно. Откат транзакции возвращает исходный файл в staging и удаляет
   только созданный вариант. Заведомо невалидное аудио получает `failed`, а
   временные сбои — `retry`. Добавлены unit-тесты и отдельный PostgreSQL-прогон
   `scripts/media-import-integration.mjs` с копией настоящего FLAC и гибридным
   контейнером из него. Лайк переносится на локальную копию после успешного импорта.
   Состояния подготовки для клиентов и выбор совместимого формата ещё предстоят.
   Проверка на тестовой ВМ: **337/337 тестов без пропусков**, отдельный импорт
   в PostgreSQL (обычный/гибридный/невалидный файл) и media API integration прошли.
   Production и GitHub не обновлялись; временные БД и копии очищены.

4. **Серверный контракт подготовки и выбора формата.** Реализовано локально:
   `/tracks/{id}/playback` принимает явный список кодеков клиента и возвращает
   ready/preparing/failed/unsupported. Поддерживаемый оригинал играет сразу,
   неподдерживаемый не выдаётся вслепую. Готовый AAC имеет приоритет согласно
   качеству; ошибки подготовки не перезапускаются бесконечным опросом.
   Строгий `/stream?codecs=...` использует те же правила. Старый API без списка
   сохраняется для совместимости. Unit-тесты и PostgreSQL-сценарий
   `preparing → обработка AAC → ready` добавлены. Для выпуска нужен перевод
   обоих клиентов; актуальный статус WEB/Android приведён ниже.
   На тестовой ВМ прошли **347/347 тестов без пропусков**. На отдельной
   PostgreSQL-БД обычный и гибридный FLAC прошли реальное создание AAC:
   до готовности строгий запрос не отдаёт неподдерживаемый FLAC, после — ready
   с AAC 192. Полное декодирование AAC и сохранность исходного SHA проверены.

5. **WEB: запуск через контракт подготовки.** Реализовано локально для локальных
   треков. Браузер объявляет свои кодеки, показывает подготовку/ошибку, отменяет
   старый запрос при переключении, паузе и смене Connect-владельца. Старый ответ
   не запускает прежнюю песню. При восстановлении сохраняются позиция и пауза;
   ожидание не перестраивает очередь. Предзагрузка не ждёт незавершённый AAC и
   использует выбранный вариант; ключи памяти различают original/normalized/AAC.
   Stream URL закрепляет вариант, чтобы сервер не подменял байты под тем же
   ключом кэша. После ошибки нативного декодера возможен AAC только для этого
   трека. Явный повтор отправляется один раз, а не при каждом опросе.
   Совместимость со старым API включается только при ответе «Маршрут не найден»;
   401/403/5xx и отсутствие трека не переключают на неподдерживаемый оригинал.
   Удалённые треки и внешний предпросмотр пока сохраняют прежний сетевой путь.
   Проверки гонок выполняются с тестовым audio-элементом; полевая проверка
   браузера остаётся необходимой. Android ещё не изменён.
   Тестовая ВМ: **368/368 тестов без пропусков**, отдельный PostgreSQL-прогон
   WEB-клиента с настоящим FLAC/гибридом, выбором AAC и HTTP Range прошёл.

6. **Кодеки старой библиотеки.** Worker дополняет `source_codec` для старых записей,
   не перечитывая известный SHA-256 и не извлекая повторно проверенные обложки.
   Исходные файлы не изменяются. Это нужно перед новым выбором формата, иначе
   записи без codec могли бы необоснованно направляться на транскодирование.
   На production проверена только статистика отсутствующих кодеков; заполнение
   production-БД пока не запускалось. Автоматические проверки добавлены.
   Дополнение codec проверено на отдельной PostgreSQL-БД тестовой ВМ.

Исходный план следующего этапа: Android — разрешение источника в фоне Media3, закрепление
варианта на все Range-запросы и раздельные ключи кэша без полной перестройки
большой очереди. Отдельно закрепить проверку готового AAC перед статусом ready.
В этот же Android-этап включить **FM-ANDROID-016** из отчёта №15: команды seek
принимаются, но FLAC возвращается к нулю. Проверить неизвестную длину входа
при частичном кэше; на момент составления плана источник исследован read-only,
гипотеза ещё не была подтверждена.

**Завершение этапа — 2026-10-14:** Android разрешает только используемый источник
на потоке Media3/предзагрузки/скачивания, не обходит всю очередь на UI.
Вариант закрепляется на все Range текущего media period, а original,
normalized_flac и AAC разделены в кэше. API сообщает размер выбранных байтов;
он передаётся экстрактору даже при частичном кэше. Старый полный кэш и ручные
загрузки сохранены. Скачивание закрепляет URL варианта и проверяет Range/длину,
не склеивает прежнюю часть с новым вариантом. При ошибке нативного декодера
AAC запрашивается только для этого трека; вся очередь не перестраивается.
AAC получает ready только после ffprobe, полного декодирования и проверки
длительности. Невалидный результат удаляется до публикации.

Robolectric/Media3 воспроизводит неперематываемый FLAC при неизвестной длине
и рабочий поиск при известной; проверены настоящий частичный кэш, Range,
закрепление варианта и полный кэш без upstream. Ошибки 401/403/5xx и отсутствие
трека не включают старый API. Проверки не заменяют звук/перемотку на телефоне.
На отдельной тестовой ВМ прошли 370/370 серверных тестов с настоящим FLAC,
импорт в PostgreSQL и WEB-контракт с реальным AAC/Range. Исходник на production
исследован read-only; его байты при проверках не изменялись.

7. **Расширенный журнал только текущей Android-сессии.** Реализовано локально:
   сессия равна жизни процесса, а не Activity. Журнал в памяти ограничен 600
   событиями/32 КиБ, не пишет каждое событие на диск; старый локальный журнал
   очищается в фоне после установки нового клиента. При смерти процесса журнал
   теряется; отправленные серверные отчёты сохраняются по прежним правилам.
   Логируются фактическая длина DataSource.open, DataSpec/Range, форматы,
   seekable, числовые данные кэша, play intent/suppression, lifecycle и ошибки
   либо медленные API-запросы по категории. Полные URL, cookie, токены, body и
   произвольные заголовки исключаются. Сервер сохраняет типизированные session,
   media и smart_cache, который ранее отбрасывался. Лимиты отчёта увеличены
   контролируемо; добавлены проверки границ, новой сессии и редактирования секретов.
   Android-тесты и debug-сборка пройдены. Изменение диагностики само по себе
   не исправляет FM-ANDROID-016; выпуск и проверка на телефоне ещё предстоят.
